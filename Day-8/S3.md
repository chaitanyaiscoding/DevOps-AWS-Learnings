

# 🚀 Day 8 – Amazon S3 (Simple Storage Service)

> Storage Backbone of the Cloud

---

# 📦 What is Amazon S3?

**Amazon S3 (Simple Storage Service)** is AWS’s object storage service.

It is designed to:

* Store unlimited data
* Deliver high durability
* Provide global accessibility
* Scale automatically

S3 is used by:

* Startups
* Enterprises
* Netflix-level systems
* Data lakes
* Backup systems
* Static websites

It is one of the most used AWS services.

---

# 💎 99.999999999% Durability (11 Nines)

Amazon S3 provides:

```
99.999999999% durability
```

That means:

If you store **10 million objects**, you might lose **one object in 10,000 years**.

This is achieved by:

* Replicating data across multiple Availability Zones
* Automatic redundancy
* Self-healing infrastructure

Even if one AZ goes down → your data is safe.

This is why S3 is considered extremely reliable.

---

# 🧠 What is S3 Technically?

S3 is:

> An object storage service.

Unlike EBS (block storage) or EFS (file storage), S3 stores:

* Files
* Images
* Videos
* Backups
* Logs
* Application assets

In S3:

* Files are called **Objects**
* Folders are logical (not real directories)
* Everything is stored inside a **Bucket**

---

# 🗂 Core Components of S3

### 1️⃣ Bucket

A bucket is:

> A container that holds objects.

Rules:

* Bucket name must be globally unique
* Naming convention usually follows:

  * lowercase
  * no spaces
  * hyphen-separated
  * company-environment-purpose

Example:

```
mycompany-dev-assets
myproject-prod-logs
```

---

### 2️⃣ Object

An object consists of:

* Data (file content)
* Metadata
* Unique key (file path)

Example:

```
images/logo.png
videos/intro.mp4
```

---

# 🌍 How Do We Access S3 Content?

Once stored, S3 objects can be accessed via:

👉 **HTTP or HTTPS protocol**

Example format:

```
https://bucket-name.s3.amazonaws.com/object-name
```

This makes S3:

* Globally accessible
* Internet-based storage
* Ideal for public content delivery

Important:

Access depends on bucket permissions.

---

# 🛠 How to Create an S3 Bucket

## Step 1

Search for **S3** in AWS Console.

## Step 2

Click → **Create Bucket**

## Step 3

Provide:

* Bucket Name (globally unique)
* Choose AWS Region

Follow naming convention:

```
projectname-environment-purpose
```

Example:

```
devopslearning-prod-storage
```

## Step 4

Click → Create Bucket

Bucket is ready.

---

# 📤 How to Upload Files to S3?

1. Open your bucket
2. Click → Upload
3. Add files or folders
4. Click → Upload

Now your data is stored in S3.

---

# ❓ What If S3 Goes Down?

This is where:

```
99.999999999% durability
```

comes into play.

S3:

* Replicates objects across multiple Availability Zones
* Maintains data integrity
* Automatically replaces failed hardware

So the chance of losing data is extremely close to zero.

That’s why enterprises trust S3 for backups and critical data.

# 🔄 Versioning in S3

S3 supports **Versioning**.

What does this mean?

If you:

* Upload a file
* Modify it
* Delete it accidentally

S3 keeps previous versions.

This protects against:

* Accidental deletion
* Overwrites
* Ransomware scenarios

Versioning = Data protection layer.

# 🌐 Hosting Static Websites Using S3

S3 can host:

* HTML
* CSS
* JS
* Static frontend apps

Enable:

→ Static Website Hosting

Then your site becomes accessible via:

```
http://bucket-name.s3-website-region.amazonaws.com
```

This is commonly used for:

* Portfolio websites
* Frontend-only apps
* Documentation hosting

---

# 🔐 Applying Security Policies to S3 Buckets

We can attach:

* IAM Policies
* Bucket Policies
* Public access settings

For example:

* Allow only specific IP access
* Allow only certain IAM users
* Make bucket private
* Make specific object public

Security is fully configurable.
